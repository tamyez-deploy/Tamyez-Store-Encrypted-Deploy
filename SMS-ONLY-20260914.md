# Customer OTP activation

Baseline: bb74367, the live deployment recorded by CranL on 2026-09-06.

Only server.js changes inside the encrypted runtime:
- Derive customerAuthSafeMode from existing safeMode and CUSTOMER_SMS_ENABLED=true.
- Pass that flag only to createCustomerAuthHandler.
- Report customer_sms_enabled on the read-only health endpoint.

Payment, supplier, notification and generic SMS handlers retain their existing safety flags.
No schema, data, UI, dependencies or customer-auth logic changes.
Seven offline assertions/tests pass, including provider failure rollback, missing credentials,
cooldown, safe-mode no-send, live-mode mocked send and independent handler wiring.
No real OTP sent during tests. End-to-end delivery still requires an owner-initiated test.

Activation requires FORJAWALY_API_KEY, FORJAWALY_API_SECRET, SMS_SENDER_ID and
CUSTOMER_SMS_ENABLED=true in CranL. Keep STAGING_SAFE_MODE enabled/default.
Rollback: set CUSTOMER_SMS_ENABLED=false and reapply the deployment environment,
or redeploy baseline bb74367. No data rollback is needed.
